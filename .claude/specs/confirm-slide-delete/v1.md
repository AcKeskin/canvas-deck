# Spec — confirm-slide-delete (v1)

## Problem
The trash button under the slide list deletes the current slide at once (`src/deck/DeckEditor.tsx:148-151`). Autosave writes the deck soon after, and Excalidraw's undo covers only objects on a canvas, not the slide list. One misclick loses a whole canvas. Vision canvas-deck v1 asks to never lose user content. Found by cycle run `2026-10-25-first-run`, audit Missing 1.

## Goals
- The trash button asks "Delete slide "<title>"?" before it deletes. An empty title reads "Untitled", as in the slide list.
- Delete removes the slide, as today. Cancel, Esc or closing the dialog keeps it.

## Non-goals
- Undo for slide-list actions.
- Asking before deleting a saved view (small, and easy to save again).
- Changing the one-slide minimum (the button stays disabled at one slide).

## User-facing behavior
- Obsidian: a modal with the question, a **Delete** button (warning style) and a **Cancel** button.
- Browser harness: the browser's `confirm` dialog.

## Technical approach
- `DeckEditorProps` gets an optional `confirm?: (message: string) => Promise<boolean>`, next to `ask`. With no `confirm`, delete works as today.
- `onDelete` captures the slide index and title, awaits `confirm`, and deletes only on `true`.
- `src/obsidian/confirm.ts`: a small `Modal` like `src/obsidian/ask.ts`, resolving `true` on Delete and `false` on any other close.
- `src/deck/deck-view.tsx` passes `confirm={(m) => confirm(this.app, m)}`; `dev/harness/main.tsx` passes `window.confirm`.

## Constraints
- Must work on Obsidian mobile: buttons only, no hover.

## Grounded context
- Audit `2026-10-25-first-run` Missing 1; the user chose a confirm dialog over an undo notice at the slice card.
- Same pattern as the rename prompt: `ask` prop on `DeckEditor`, Obsidian modal in `src/obsidian/ask.ts`, `window.prompt` in the harness.
- No project memories apply.

## Open questions

## Verification criteria
- `tests/e2e/deck.spec.ts`: dismissing the dialog keeps all slides; accepting deletes the current one. Playwright dismisses dialogs by default, so tests that delete must accept it.
- `npm run build` (includes `tsc --noEmit`) and `npm test` pass.
- The Obsidian modal is read in code review; it cannot run in the harness.
