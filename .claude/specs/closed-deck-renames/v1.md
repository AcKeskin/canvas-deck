# Spec - closed-deck-renames (v1)

Delta-only spec from cycle run 2026-10-25-run4, slice A9. No interview: the confirmed slice settles the approach.

## Problem
Image paths live in `slide.images` and note paths in `obsidian-note:` links, both inside `%%cdeck` JSON blocks. Obsidian's own link updater never sees them. `src/main.ts` `vault.on("rename")` only calls `DeckView.renameLinks` on open deck views. A deck that is closed when the image or note is renamed keeps the old path, and the embed breaks. The README promises "Renames are followed".

## Goals
- A rename updates every deck note in the vault that links the old path, open or not.
- One pure helper does the per-slide mapping for both paths.

## Approach
- Add `renameDeckLinks(deck, oldPath, newPath): Deck` to `src/deck/deck-model.ts`. It maps `renameNote(renameImage(s.data, ...), ...)` over the slides and returns the same deck when nothing changed. `DeckView.renameLinks` calls it.
- In `src/main.ts`, after the open-view pass, walk `vault.getMarkdownFiles()` that pass `isDeck` and have no open deck view. Skip a file when its text lacks `oldPath` (`vault.cachedRead` then `includes`). For the rest, run `vault.process(file, text => ...)`: `parseDeck`, `renameDeckLinks`, and `serializeDeck` only when the deck changed; otherwise return `text` as is.
- `vault.process` reads the current text itself, so it is safe if the file changed since the cached read.

## Rejected approaches
- Open every closed deck in a hidden `DeckView`. Heavy, and it mounts React for a text edit.
- Re-reading each deck without the `includes` check. Parses every deck on every image rename.
- Regex replace on the raw text. Paths sit inside JSON strings; escaping rules make this fragile. The parsed helper is the same code the open view uses.

## Open point (check in step 3, not assumed)
Whether Obsidian fires `rename` once per child on a folder rename. The handler skips paths that are not images or notes, so a folder rename is followed only if child events fire. If they do not, this slice does not add folder support; write a card.

## Non-goals
- Deck notes renamed or moved themselves (they hold no path to themselves).
- Updating links when a file is deleted.
- Folder rename support if child events do not fire.
