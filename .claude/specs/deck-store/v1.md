# Spec — deck-store (v1)

## Problem
canvas-engine stores one slide per `.cslide` file. A deck needs many slides, their order and speaker notes in one vault file, in a form Obsidian can search and link.

## Goals
- One markdown note per deck, flagged with `canvas-deck` frontmatter.
- Per slide: `## Title`, speaker notes as plain markdown, then a `%%cdeck … %%` block holding the slide JSON (canvas-engine SlideData).
- Pure parse/serialize with a format version.
- Reload from disk when the file changes outside the view and there are no unsaved edits.
- Drop `.cslide` single-slide files.

## Non-goals
- Showing slides from other decks.
- Decks above ~50 slides tuned for speed.
- Compressing slide data.

## User-facing behavior
- "New deck" creates `Untitled deck.md` with one slide and opens it in the deck view.
- Any markdown note with `canvas-deck` frontmatter opens in the deck view; a command switches it back to markdown.
- Notes typed in the deck view appear as text in the note, findable by search.

## Technical approach
- Picks made without an interview (user asked to run to a demo): markdown file, drop `.cslide`, reload-if-clean, no cross-deck slides, ~50 slides.
- Parser splits on `%%cdeck` blocks; text before each block is that slide's title line and notes.

## Constraints
- Must not break Obsidian's markdown rendering of the note.

## Grounded context
- vision canvas-deck v1, module deck-store.
- spec canvas-engine v1: SlideData is the per-slide payload.

## Open questions
- Very large decks may make the markdown file slow to edit in source view.

## Verification criteria
- Unit tests for round trip, legacy/missing fields, and notes with headings or `%%` text.
- Browser test: edit deck, serialize, parse, compare.
