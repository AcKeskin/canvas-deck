## Step 2: Pure helper, open view uses it
- Files: src/deck/deck-model.ts, src/deck/deck-view.tsx
- Outcome: `export function renameDeckLinks(deck: Deck, oldPath: string, newPath: string): Deck` with the doc comment "Returns the same deck if nothing changed." `DeckView.renameLinks` becomes: guard `this.deck`, `const next = renameDeckLinks(this.deck, oldPath, newPath)`, return if `next === this.deck`, else assign, `requestSave()`, `mount()`. Drop the `renameImage` and `renameNote` imports from `deck-view.tsx` only if nothing else there uses them (`isImagePath` and `isNotePath` stay if used).
- Verification: `npx vitest run tests/deck-model.test.ts` passes; `npm run build`
- Serves criteria: [1, 3]

## Step 3: Vault pass for closed decks
- Files: src/main.ts
- Outcome: in the `rename` handler, after the open-view pass, call a new private `renameInClosedDecks(oldPath, newPath)`. It collects the paths of open deck views (`getLeavesOfType(DECK_VIEW)` with `(l.view as DeckView).file?.path`), loops `this.app.vault.getMarkdownFiles()`, skips non-decks (`isDeck`) and open ones, skips files whose `cachedRead` text lacks `oldPath`, and runs `vault.process(file, text => { const deck = parseDeck(text); const next = renameDeckLinks(deck, oldPath, newPath); return next === deck ? text : serializeDeck(next); })`. Each file's failure shows `new Notice(\`Cannot update links in ${file.path}.\`)` with `console.error`; no floating promise (`void` the call, catch inside). Check how `DeckView` exposes its file before writing this; match existing style.
- Verification: `npm run build`; `npm test`
- Serves criteria: [2, 4]
