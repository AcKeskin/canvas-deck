# Plan - image-errors (v1)
Spec: ../../specs/image-errors/v1.md

## Done-criteria (from spec)
1. A failed pasted-image save shows one notice, keeps the image in memory, and is not retried on later changes
2. A failed vault-image insert (command or drop) shows a notice; no unhandled rejection
3. `npx playwright test tests/e2e/harness.spec.ts` passes with a rejecting-store test
4. `npm run build` and `npm test` pass

## Step 1: Harness store can fail
- Files: dev/harness/main.tsx
- Outcome: `window.harness.failSave` (boolean, default false) makes `store.save` reject with `new Error("save failed")`; `window.harness.saveCalls` counts `store.save` calls. Both declared in the `declare global` harness type and set in the `window.harness = {...}` object.
- Verification: `npm run build`
- Serves criteria: [3]

## Step 2: Failing test first
- Files: tests/e2e/harness.spec.ts
- Outcome: test "failed pasted-image save is reported once and not retried": collect `page.on("pageerror")`; set `harness.failSave = true`; add a pasted file and image element as in the existing paste test; wait for `harness.saveCalls === 1`; make two more scene changes (move the image with `api.updateScene`); assert `saveCalls` is still 1, `slide.images` is `{}`, the image element is still in `api.getSceneElements()`, and no page errors.
- Verification: `npx playwright test tests/e2e/harness.spec.ts --reporter=line` (env CHROMIUM_PATH from setup.md) fails on the new test before step 3 (saveCalls grows past 1 and/or a page error)
- Serves criteria: [1, 3]

## Step 3: Engine stops dropping the rejection
- Files: src/canvas/engine.ts
- Outcome: new `private failedSaves = new Set<string>()`; `saveFile` returns early for ids in it; a `catch` adds the id and calls `console.error("Canvas Deck: cannot save pasted image", e)`. One-line comment says the store already told the user.
- Verification: `npx playwright test tests/e2e/harness.spec.ts --reporter=line` passes, all 5 tests
- Serves criteria: [1, 3]

## Step 4: Obsidian notices
- Files: src/obsidian/vault-image-store.ts, src/main.ts, src/deck/deck-view.tsx
- Outcome:
  - `vaultImageStore.save` wraps its body in try/catch; the catch shows `new Notice("Cannot save the pasted image to the vault. It stays on the slide until the deck closes.")` and rethrows.
  - `src/main.ts` insert-image picker: `v.engine?.insertImage(f.path).catch(() => new Notice(\`Cannot insert ${f.path}.\`))` (keep a `void` or return so nothing floats; match the file's style).
  - `src/deck/deck-view.tsx` `onDrop`: the same `.catch` with the notice for `file.path`.
- Verification: `npm run build`, then `npm test`
- Serves criteria: [1, 2, 4]
